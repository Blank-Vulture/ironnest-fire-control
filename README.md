# Iron Nest Fire Control

Iron Nest 用の射撃補助ツール。画面は 2 つあります。

| 画面 | 役割 |
| --- | --- |
| **PLOTTING**（標定） | 偵察兵の報告から目標の位置を割り出す |
| **FIRE CONTROL**（射撃管制） | 方位角と射程から仰角・装薬・飛翔時間・発射時刻を出し、砲塔の旋回が最小になる順に左右の砲へ振り分ける |

標定した点はそのまま射撃順に送れます。ゲーム内では目標 1 体ごとに
「偵察兵の報告を地図に起こす → 赤線を引く → クリップボードに方位角と射程が記録される →
弾道計算機でカードを刷る」を繰り返しますが、このツールはその全部を引き受けます。

## PLOTTING — 標定

偵察兵は自分の位置をグリッドで報告し（`Spotter1 - I9 9:1`）、そこから見た目標の
方位や距離を個別に寄こします。それを突き合わせて位置を割り出します。

画面は上から **IRON NEST → 既知点 → 地図 → 標定** の順に並びます。誰がどこにいるかを
先に決め、それを地図で確かめてから目標を割り出す、という順で進みます。

1. クリップボードの名簿をどこかの欄に**貼る**と、IRON NEST と偵察兵に振り分けます。
   既定で偵察兵は 3 人ぶん用意してあります。
2. **標定**に観測を並べ、それぞれ観測元・**方位**・**距離**を入れる。
3. 推定位置と **IRON NEST からの方位・距離**が出るので、**射撃順に追加**を押す。

### 既知点

座標が分かっている点は、役割ごとに 2 列に分けて並びます。

- **偵察兵** … 報告を寄こす側。撃破の切り替えが付きます
- **基準点** … 位置だけが分かっている点。High Command から座標をそのまま渡されることがあるので、
  三角測量を経ずに直接置けます。観測元にも使えます

撃って確かめた標定も、由来が違うだけで同じ基準点なので **実測** の印を付けて同じ列に並びます。

### 戦術地図

上部の地図に、距離の報告は**円**、方位の報告は**直線**で描かれます。どこで位置が
決まっているのか、候補が 2 つあるならどれだけ離れているのかが形で分かります。

色はゲーム内のマーカートークンに合わせています。

| | 色 |
| --- | --- |
| IRON NEST | 黄 |
| 偵察兵 | 青 |
| 基準点 | 緑（ゲーム内の A〜E トークンに合わせています） |
| 標定した点・候補地 | 赤 |

**誰の報告かは色ではなく「強調」で示します。** 色相は種類（味方・敵・自機）に使い切って
いるので、出所まで色に載せると両方が読みにくくなります。かわりに、点にホバーする（既知点の
一覧の行でも、地図の印でも可）と**その点が出した円と線だけが残り、他は沈みます**。
全部を一度に見分けるより、1 人ぶんを確かめる方が実際の使い方に合っています。

- **拡大縮小** … ホイール、二本指のつまみ、右上の `＋` `−` `全体`
- **パン** … 掴んで動かす
- **まだ解けていない標定の線は破線**になります。線は観測元の色で引くので、どの 2 本が
  同じ目標のものかは見ただけでは分かりません。解けていない線が実線のまま並ぶと、
  関係のない線どうしの交わりを候補と読み違えます
- **印にホバー／タップ** … 「目標#1　J3 0:0」のように名前と座標が出ます。タップすると固定されます

寄せても印と文字は膨らまず、画面上の大きさを保ちます。目盛りの A〜T・1〜10 は
見えている範囲の縁に貼り付くので、寄せている最中でも座標を読めます。

方位どうし・距離どうし・方位と距離、どの組み合わせでも成立します。拘束が 2 つそろえば解けます。

観測元には**偵察兵・基準点・着弾点・IRON NEST**のほか、**先に解けた他の標定**も選べます
（輪になる組み合わせだけは選択肢から外れます）。

### 候補が 2 つ出たとき

距離 2 つや方位と距離の組は交点が 2 箇所に出ます。

**片方が地図の外に落ちる場合は、盤面の中の方を目標として採用します**（外に敵はいないため）。
この場合、候補は 1 つに決まるので曖昧さは残りません。

両方とも盤面の中なら、**候補地 1** と **候補地 2** として並べます。地形や報告の文面で絞るか、
観測をもう 1 つ足してください。**撃って確かめる**を押すと候補地 2 を射撃順に入れられるので、
1 発撃って当たるかどうかで潰す、という決め方もできます。

### 緊急移動で自機の位置が分からなくなったら

`EMERGENCY MOVE` で跳ぶと自機の座標が不明になります。**IRON NEST** の区画の
**座標を更新**を押してください。現在座標も補給隊の設定も、この区画にまとまっています。

緊急移動は発動した地点のまわりに散るだけで、いきなり遠方へは飛びません。つまり
移動前の座標が手がかりになります。そこで**補給隊 2 隊をどのタイルへ呼ぶかを自動で決めます**。
2 隊からの視線がなるべく直角に近く交わり、かつ両隊とも盤面に収まる向きを選びます
（浅い角度で交わると、報告のわずかなぶれが大きな位置の誤差になるため）。

`補給隊 1` `補給隊 2` の欄が同じ区画に開くので、あとは**戻ってきた報告（方位、あるいは
補給隊自身の細かい座標）を入れるだけ**です。解けたら **現在地にする** を押すと IRON NEST の
座標が書き換わり、以降の射撃諸元がその位置で計算されます。用が済んだら **片付ける** で畳めます。

地図では、この割り出し中の点だけ敵の赤ではなく自機の黄で描かれます。

位置報告の要請ではタイル単位（`A1` や `I2`）しか指定できないので、要請先もタイル単位で出します。

### 段を重ねる（target chaining）

任務によっては 1 段では終わりません。たとえば

> 偵察兵 3 人の距離が重なる地点を出す → その地点からの方位と、偵察兵 3 からの方位で目標を出す

のように、いま出したばかりの点を次の観測元に使うことがあります。そこで**観測元には
既知点だけでなく、先に解けた標定点も選べます**。解ける順に自動で確定していくので、
定義の順番は問いません。輪になる組み合わせは選択肢から外れます。

ただし**推定した点を観測元にすると、その誤差はそのまま持ち越されます**（Iron Nest Wiki も
同じ警告をしています）。累積ぶんを別に出すので、段を重ねるほど広がっていくのが見えます。

- **候補が 2 つ出る場合** … 距離 2 つや、方位と距離の組は交点が 2 箇所に出ます。
  両方を並べるので、地形や報告の文面で絞るか、観測をもう 1 つ足してください。
- **交差角が浅い場合** … 方位 2 本が平行に近いと誤差が大きく開くので警告します。
- **報告の食い違い** … すべての報告が同じ 1 点をどれだけ指しているかを m で出します。
  大きければどこかの報告が間違っています。
- **交わらない場合** … 情報不足なのか、報告が矛盾しているのかを区別して伝えます。

### グリッド

タイルは **A1 から T10**、1 タイル **1km 四方**。各タイルは 10×10 に分かれ、
`0:0` から `9:9` のマスは **100m 四方**です。**A1 が左下、T10 が右上**で、
列 A→T が西→東、行 1→10 が南→北。サブ座標も 0→9 が左→右・下→上です。

### 撃破の優先度

優先度はカードの見出しにあります。射撃順では **撃った** のすぐ左、標定では
名前と座標の間——どちらも元から空いていたところです。**高価値** を付けた目標は、
旋回が遠くても先に撃ちます。

| 優先度 | 扱い |
| --- | --- |
| 高価値 | 旋回を余分に払ってでも真っ先に潰す |
| 優先 | 通常の目標より先に撃つ |
| 通常 | 旋回がいちばん少ない順に撃つ（**既定**） |

**既定の「通常」がいちばん下の段です。** 急ぐものに印を付けるだけで、ほかは
自動で後ろへ下がります。下に「後回し」の段を置くと、急がない目標をわざわざ
指定して回ることになるためです。

**段の中では、これまでどおり旋回が最小になる順に並びます。** 段の中まで方位を
無視すると旋回だけで時間を食い潰すためです。段を跨ぐときは直前の段を撃ち終えた
方位から続けて寄せるので、戻りの旋回も最小になります。

段そのものは跨いで混ぜません。「高価値なのに旋回が近いから後回し」を許すと、
なぜその順なのかが画面から読み取れなくなります。

## 2 つの画面の連動

標定と射撃順は紐づいて動きます。片方だけ直して食い違う、という状態を作らせません。

| 起きたこと | 連動 |
| --- | --- |
| 標定を消す | そこから出した射撃順のカードも消える |
| カードを消す | 元の標定も消える（**実測座標を持つ**か、他の標定の観測元になっているときは残す） |
| カードを撃ち終える | 標定に **完了** が付く。カードはその場に残り、左右そろった行だけ畳まれます |
| 観測基準点を撃って結果を報告 | 標定に **命中** / **不発** が付き、実測座標が確定する |
| 観測を足す・砲座が動く | カードの方位・距離・仰角・装薬・飛翔時間がすべて追従する |
| 弾種・優先度を変える | どちらの画面で変えても、もう片方に映る |

標定カードには **観測基準点** と **攻撃対象** の印があり、独立に持てます（撃つ相手が
他を測る基準を兼ねることもあるため）。

- **観測基準点** … 位置を確かめて使う点。**実測座標**の欄が開き、射撃順へ送ると
  **確認射撃**のカードになります。印を付けると名前が **Alpha**、**Bravo** …と
  自動で振られます（`＋ 基準点` で直接置いたものとも名前を取り合いません）。
  ゲーム内の報告が「Alpha からの方位角 300°」と読んでくるので、それに合わせてあります
- **攻撃対象** … オフだと射撃順に送れない。基準点を誤って撃たないための歯止めです

### 観測基準点を撃って確かめる

観測基準点は推定値なので、そのままでは誤差が下流へ積み上がります。撃って確かめると
推定値が**実測値**に変わります。

射撃順に送ると、そのカードだけ **確認射撃** の欄が出ます（普通の攻撃カードには出ないので、
撃つ目的を取り違えません）。

- **命中** … その座標に実際にいたと分かる。標定の **実測座標** が自動で埋まり、誤差 0 で確定。
  下流の標定に持ち越していた誤差も消えます
- **不発** … 推定がずれていた。候補が 2 つあればもう一方で確定し、1 つしか無ければ
  「実測座標を入れ直してください」と促します

**実測座標**は手でも直せます。入っている間は三角測量より優先され、そこが位置になります。

確定した基準点は **既知点** の **基準点** 欄にまとまります。実測で確かめた座標は、
偵察兵を失えばもう作り直せません。そこで、この座標を持つ標定は**片づけに巻き込まれません** —
射撃順のカードを消しても、標定と座標はそのまま残ります。推定に戻したいときは `↺` を押してください。

同じ点を二重に射撃順へ送ることもできません（送ったボタンは**追加済み**になります）。
撃ち終えた標定は地図でも輪が重なって、残っている目標と見分けられます。

### 外れ弾を観測に変える

照明弾や、目標から外れた着弾では、**着弾点からの方角とおよその距離**が報告されます。
方角は曖昧ですが**距離は正確**なので、これがそのまま観測になります。

着弾点は自分が撃った座標そのものなので、位置は分かっています。つまり
**着弾点を中心とした距離円**がもう 1 本引ける、ということです。

普通の攻撃カードの **不発** を押すと、撃った座標が控えられます。そこに報告された
距離を入れて **観測に加える** と、着弾点が既知点に登録され、その標定に距離の観測が
足されます。曖昧だった候補が 1 つに絞れることもあります。

着弾点は 既知点 の 基準点 欄に **着弾** の印で並び、地図には白い星と距離の円が出ます。
撃った座標が違っていたら、その場で直せます。

### 見込み誤差と次の一手

三角測量の式は正確でも、入ってくる報告には幅があります。方位は入れた桁数まで、
観測元の座標は 100m 四方のマスまでしかありません。その幅が位置の誤差にどれだけ
化けるかは、観測どうしの**交わり方**で決まります。

見落としやすいのは**観測元の座標**のほうです。マスの ±50m は方位の ±0.5° より
小さく見えますが、浅く交わればどちらも同じ倍率で増幅されるので、観測元が近いほど
こちらが効いてきます。しかも 100m マスより細かくは報告できないので、
**報告を丁寧にしても縮みません**。角度の良い観測を足すしか手がない。

観測元 2 点がそれぞれ 4km の場合の見込み誤差です。

| 交差角 | 方位を「300」と入力 | 方位を「300.0」と入力 |
| --- | --- | --- |
| 90° | ±86 m | ±71 m |
| 45° | ±112 m | ±87 m |
| 30° | ±166 m | ±133 m |
| 20° | ±249 m | ±201 m |
| 15° | ±333 m | ±269 m |
| 5° | ±1025 m | ±812 m |

方位は 1 つの欄に打ちます。報告の小数第 1 位はたいてい 0 なので、**点を打たずに
`300` と入れれば `300.0` として扱います。** 0 以外だったときだけ `300.4` と
点まで打ってください。

`300` を「300 度前後」とは受け取りません。報告の方位は必ず小数第 1 位まで来る
ので、書かなかった桁は 0 と分かっているためです。ここを取り違えると、浅く交わる
標定で誤差を実際の 10 倍に見積もります。小数第 2 位まで読めるなら、そのぶん
さらにせまく扱います。

距離のほうは書いた桁のとおりに読みます（`3.71` なら ±5m、`4` なら ±500m）。
方位と違って決まった桁が無いためです。

ただし表のとおり、浅い交差では小数まで入れても足りません。右の列が頭打ちに
なっているのが座標の壁です。

標定カードは、報告を実際に振って解き直し、答えがどれだけ動くかで誤差を測ります。
そのうえで次の一手を出します。

- **観測を足すなら、どの方角の線上から見てもらえばよいか**（いまの視線に直角に近い向き）
- **照明弾** … 誤差が照明弾の範囲（500m）に収まるなら、1 発で照らせます。撃つ座標も出します
- **偵察飛行** … 照らしきれない誤差なら、ここへ 1 発撃って着弾点まわりの写真を撮ります
- **弾種との突き合わせ** … 見込み誤差と効果半径から**命中の見込みを確率で**出します

#### 当たる見込みの出し方

見込み誤差はばらつきの 1 標準偏差にあたるので、そこから確率を出します。浅い交差
では誤差が一方向に細長く伸びるため、いちばん延びる向きの正規分布として見ます
（全方向に均すより辛く出るので、撃つ判断はこちら側に寄せてあります）。

| 命中の見込み | 見立て |
| --- | --- |
| 90% 以上 | 撃てる見込み |
| 60〜90% | 当たる公算はあるが確実ではない |
| 35〜60% | 当たるかどうかは五分五分 |
| 35% 未満 | このまま撃つと外れる公算 |

以前は「誤差が効果半径の半分までなら良し」と割合で切っていましたが、切る場所に
根拠が無く、付ける名前も実態と合っていませんでした。効果半径のちょうど半分の
誤差は命中 95% あるのに「五分五分」と呼び、1.35 倍で「外れる公算」と言い切って
いたものが実際は 54% でした。**ATMC のような効果半径の大きい弾でこれが目立ちます**
（±1745m の誤差でも効果半径 3000m なら 9 割方当たります）。

同じ手順で撃っているのに当たったり外れたりするのは、たいていここが原因です。

#### 候補が 2 つあるとき

距離だけで解くと交点が 2 つ出ます。方位線が距離円を横断するときも 2 つ出ます。
標定カードは**タブで候補を切り替え**られ、座標・見込み誤差・命中の見込み・
射撃諸元・見立てのすべてが切り替わります。**既定で開くのは当たりやすいほう**で、
そのタブに「先に撃つ」と付きます。`撃って確かめる` は、いま見ている候補へ撃ちます。

当たりやすさが並んだときは、報告全体との**食い違いが小さいほう**——つまり本物
らしいほうを採ります。どちらも 0 なら報告からは決められないので、順番は動かし
ません（勝手に並べ替わると、見ていた候補が入れ替わってしまいます）。

**たいていの配置では、2 つの候補はほぼ同じ当たりやすさになります。** 距離 2 本の
候補は中心線をはさんだ鏡像なので誤差も鏡像になり、方位線と円の場合も弦の両端で
円と直線の交わる角度が等しいためです。差が付くのは、円をかすめるように横断して
2 つの交点が方位の元から別々の距離に出るとき。方位のぶれは距離に比例するので、
そこで初めて差が出ます（実測で ±414m 対 ±829m、命中 45% 対 24% の例があります）。

見込み誤差は**追っている候補の動き**だけを測ります。解き直すたびにどちらを
「本命」と名乗るかが入れ替わるので、返ってきた座標をそのまま測ると候補間の距離が
誤差に化けてしまいます。

照明弾・偵察飛行の勧めは、候補が 1 つに決まってから出ます。候補が割れている
間は「候補を 1 つに絞る」がすでに照らす場所を出しているので、そこへ重ねると
「間を照らせば両方を確かめられます」と「照らしきれません」が並んでしまいます。

#### 標定を鎖にするとき

解けた標定点は次の標定の観測元に使えますが、**その点自身の誤差はそのまま次に乗ります**。
交差角 15° で ±337m ぶれている点を観測元にすると、次の標定がどれだけ良い角度で
交わっても ±244m より良くはなりません。鎖の根元を良い角度で取るのが先です。

観測元の誤差には 2 種類あります。

- **マスで座標を入れた点**（偵察兵の報告、実測した基準点）… 100m の幅が必ず付きます。
  報告に載る座標がそこまでしかないので、**丁寧にやっても縮みません**
- **測って割り出した点**（他の点からの方位と距離で解いた点）… マスの幅に縛られません。
  地図で直接測った線から割り出せば、その線の精度がそのまま効きます

### 保存を捨てる

画面の右下に **保存をすべて消す** があります。押すと件数と警告が出て、もう一度
押すと消えます。**↩ の取り消しは効きません。**

表記を変えても、すでに保存された名前までは変わりません。「観測員」と呼んでいた
頃に置いた偵察兵は、その名前のまま残り続けます。名前は手で直せる値なので、
既定値を変えても過去のぶんには届かないためです。古い呼び名を抱えたまま使いたく
ないときに使ってください。

消えるのは `iron-nest-timing/` で始まる保存だけです。GitHub Pages は
`<ユーザ名>.github.io` という 1 つのオリジンを全リポジトリで共有するので、
まるごと消すと同じところに置いた別のページの保存まで巻き添えになります。

### 元に戻す

標定とカードは互いに消し合うので、1 回の誤操作で両方まとめて消えます。消す・畳む・
座標を書き換えるといった構造を動かす操作は **⌘Z / Ctrl+Z**（または上部のボタン）で
戻せます。文字の打ち直しは入力欄の取り消しに任せるので、横取りしません。

### 撃破された偵察兵

偵察兵の行の左の印を押すと撃破扱いになります。**これから新しい報告はもらえない**ので
観測元の選択肢から外れますが、**すでに受け取っている報告はそのまま使えます**
（撃破される前の報告なので）。

地図でも印が中抜きの丸に × が重なった形に変わり、名前に「（撃破）」が付きます。
その偵察兵が出した円や線は残るので、報告が生きていることも見て取れます。

## 使い方

1. ゲーム内クリップボードの下線部を見て、**数字だけ**を打つ。
   方位角 → `Enter` → 射程 → `Enter` で 1 件登録。テンキーから手を離す必要はありません。
   単位（`°` `km`）も区切りの `/` も打たなくて構いません。
2. カードが射撃順に並びます。1 行が「左を撃つ → わずかに旋回 → 右を撃つ」の 1 組です。
3. 着弾時刻の指定がある目標だけ、着弾時刻を入れると発射時刻が出ます。
4. 撃ったら **撃った** を押す。薬莢が排出されて次弾が送り込まれ、射撃順が組み直されます。

OCR などで `273.9° / 6.16km` の書式ごと持ってきた場合は、そのまま**貼り付け**れば読みます。
複数行まとめて貼れば一度に登録されます。

カード上で変えられるもの:

| 項目 | 既定 | 備考 |
| --- | --- | --- |
| 弾種 | HE | 20 種。射程・仰角・飛翔時間には影響しません |
| 装薬 | 自動 | 届く最小の装薬。上げると仰角が下がり飛翔時間も短くなります |
| 砲 | 自動 | 射撃順から交互に割り当て。`L` / `R` を押すと固定 |
| 着弾時刻 | — | 数字だけ打てばコロンが入ります（`101010` → `10:10:10`） |

## 計算

すべてゲーム内の弾道計算機と同じ式です（近似ではありません）。

**仰角** — 装薬 N の最大射程は `5N km`。0 km を 0°、最大射程を 60° として線形に写す:

```
仰角 = 距離 × 12 ÷ 装薬数
```

ゲーム内で提示される手計算の式と一致します。最低仰角の制限はありません。

**飛翔時間** — 弾速は弾種によらず基本 0.7 km/秒。装薬が smoothstep で倍率を掛けます:

```
u    = (装薬数 − 1) ÷ 5
弾速 = 0.7 × [0.3 + 0.7 × (3u² − 2u³)]   km/秒
飛翔 = 距離 ÷ 弾速
```

装薬 1〜6 での弾速は `0.21000 / 0.26096 / 0.38248 / 0.52752 / 0.64904 / 0.70000` km/秒。
発射レバーを引いてから砲弾が出るまでのわずかな間は含まれません。

**発射時刻** — `着弾時刻 − 飛翔時間`。どちらもゲーム内の時間軸の値なので、
出てくる発射時刻もそのままゲーム内時計で読めます（現実の時計とのズレは無関係）。
端数は近い方の秒に丸めます。

## 装填の見取り図

砲塔の図の左右の余白に、その砲がこれから撃つ弾が上向きに並びます。弾体には弾種コードが
縦書きで入っているので、**左に何を、右に何を込めるか**が弾の並びそのもので分かります。
弾は砲塔側の端から詰まり、いちばん砲に近いものが次弾です。

- **塗りつぶしの弾** … 全体で次に火を噴く 1 発。その砲身と `L` / `R` も橙になります。
- **輪郭だけの弾** … その砲の次弾。左右とも装填できるので両側に出ます。

**撃った** を押すと薬莢が排出され、残りが砲側へ送り込まれます。

### 装填数の上限と補給

砲塔後部の回転式弾倉は **1 基 6 発**、これが 2 基あって即応弾は計 12 発です。
これを超えるぶんは補給トラックから砲塔後部へ揚弾することになります。

そこで、片側 7 発以上を抱えている砲は**弾架が 2 段**になります。

- **1 段目**（実線） … 弾倉の即応弾 6 発
- **2 段目**（破線） … まだ砲塔に積んでいないぶん

1 発撃つごとに残りが砲側へ送られ、2 段目の弾は 1 段目へ降りてきて実線に変わります。
見出しには `8 発 補給 2` のように、補給が要る発数が出ます。

射撃順の側でも、即応弾を撃ち切る 1 発の手前に **「下記の弾を補給してください」** が挟まり、
その砲に何を何発目に上げればよいかが順に並びます。図に出るのは 2 段（12 発）までで、
それを超えるぶんは `+N` と出ます。

## 射撃順

砲塔の旋回は左右の砲で共通なので、連続射撃の律速は方位の修正です。そこで:

- 目標を方位順に並べ、**いちばん広く空いている隙間の直後から一方向に回る**。
  こうすると全目標を撃ち終えるまでの旋回量が「一周 − 最大の隙間」で最小になります。
- 左右の砲を**交互に**割り当てる。片方が飛んでいる間にもう片方を装填でき、
  旋回もカード間に表示されるぶんだけで済みます。
- 砲を手で固定して同じ砲が続いた場合は、装填待ちになる旨を表示します。

1 発撃つと、砲塔はその目標の方位を向いたままになります。そこで **撃った** を押した目標の
方位と使った砲を引き継ぎ、続きから組み直します。

- 残りの目標を覆う弧に対して、**手前端に寄って時計回り**に舐めるか、**奥端に寄って反時計回り**に
  舐めるかの、寄せる距離が短い方を選びます。後者では左回りの旋回が出ます。
- 左右の割り当ても直前に使った砲の続きから振ります。これをやらないと 1 発撃つたびに
  左右が入れ替わり、先に装填しておいた弾が無駄になります。

## 開発

```
npm install
npm run dev        # 開発サーバ
npm test           # ロジックのテスト
npm run typecheck  # 型チェック
npm run build      # dist/ を生成
```

計算ロジックは UI から切り離して [`src/lib/`](src/lib/) に置いてあります。

| ファイル | 役割 |
| --- | --- |
| [`ballistics.ts`](src/lib/ballistics.ts) | 仰角・射程・弾速・飛翔時間・方位差 |
| [`time.ts`](src/lib/time.ts) | 時刻と時間の解析・整形。内部表現は「0 時からの経過秒」 |
| [`shells.ts`](src/lib/shells.ts) | 砲弾 20 種の諸元 |
| [`guns.ts`](src/lib/guns.ts) | 左右の砲の識別 |
| [`targets.ts`](src/lib/targets.ts) | 目標の取り込み・解・射撃計画 |
| [`grid.ts`](src/lib/grid.ts) | 戦術地図のグリッドと km の変換、方位と距離 |
| [`triangulate.ts`](src/lib/triangulate.ts) | 観測 1 組からの位置の割り出し |
| [`survey.ts`](src/lib/survey.ts) | 点の網を解ける順に確定させる。誤差の持ち越しもここ |
| [`convoy.ts`](src/lib/convoy.ts) | 補給隊をどのタイルへ呼ぶかの割り出し |
| [`route.ts`](src/lib/route.ts) | 画面の切り替え。静的配信なのでハッシュで持つ |

戦術地図は [`GridMap.tsx`](src/components/GridMap.tsx)。viewBox の 1 単位を 1km にとってあるので、
距離の円も方位の線もそのままの数値で描けます。線の太さだけ倍率に引きずられないようにしています。

機能を足すときは、まずここに純粋関数とテストを足してから UI を繋いでください。
UI 側（[`src/components/`](src/components/)）は表示だけを持ち、計算は持ちません。

> 入力欄の並びと結果の並びは分けてあります。結果は方位順に並べ替わるので、
> 入力欄をその順で描くと、打っている最中に行が動いて別の目標に文字が入ります。
